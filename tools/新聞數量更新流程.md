# 新聞數量更新流程（當初怎麼抓的）

> 以後新聞數量的更新，一律在**網站健檢這個專案**進行。
> 本文記錄 2026-08 建置新聞監測儀表板時的原始抓取方法，供日後更新沿用。

## 一、數字的定義

| 名詞 | 定義 |
| --- | --- |
| 統計期間 | `2025.08.01`–`2026.07.31`（114 學年度，10.5 個月） |
| 目標值 | 每系 **20 則**／學年 |
| 新聞數量 | 期間內全部則數 **扣除**「非新聞」後的則數，這才是達標計算基準 |
| 來自校網 | 該則已由校官網文章頁以本系 `#hashtag` 串接（含學系轉貼與校網獨家） |
| 學系自行建置 | 學系網站自己發布、校網未串接者 |
| 非新聞 | 公告／報名／招生／活動預告等，經 v4.0 審核判定不屬新聞稿，已從新聞數量扣除 |

## 二、四條資料來源（原始抓取方式）

### 1. 學系自有新聞 — RSS 分頁

各系網站的 `/news/feed/`，第二頁以後用 `?paged=N`。實測第 1 頁 100% 為自站文章，天然乾淨。
RSS 解析不到時，退回解析 WordPress 新聞列表頁 HTML。

### 2. 校級新聞 — 校網 JSON API

```
https://www.fcu.edu.tw/wp-json/api/news?offset=0&limit=100
```

分頁往回抓到最舊日期早於 `2025-08-01` 為止（約 200 則），存成 `school_news_full.json`，
成為儀表板裡的 `SCHOOL_RAW`。

### 3. 學系歸屬 — 逐篇抓文章頁的 hashtag

對每一篇校網文章實際發出請求，從 HTML 擷取：

```python
TAG_RE = re.compile(r'class="m-tags__item">#\s*([^<]+?)\s*</a>')
```

產出 `url_cats.json` → 儀表板裡的 `URL_CATS`。
**這是即時抓取結果，比快取的 `SCHOOL_RAW` 準確完整**，程式判定校網來源時以它優先。

### 4. 非新聞判定 — v4.0 審核（News Gatekeeper）

`review_news_v4.py`，四道關卡依序判定，不產生加權分數：

- Gate 1 新聞類型判定 → 非新聞立即 🔴 停止，不再往下審
- Gate 2 新聞完整度（列出缺漏要素，不計分）
- Gate 3 新聞照片素材（張數／圖說／重複圖，不做影像辨識）

輸出 `article_review_v4.json` → 儀表板裡的 `NEWS_REVIEW = {url: {nn:1, why:'理由'}}`。
儀表板上**只標示非新聞**，不顯示完整度與照片建議（2026-08-01 使用者決定）。
原規格的「AI 語感偵測」關卡同日移除——偵測到的是公關腔而非 AI 生成文，與設立目的不符。

## 三、合併與計算（儀表板內 `D.forEach`）

1. 取學系自有新聞中落在期間內者，逐篇判定 `fromSch`（`URL_CATS` 含本系名稱，或網址屬 `www.fcu.edu.tw`）
2. 補上「校網有標記本系但學系尚未轉貼」的獨家則數（以網址與標題去重）
3. 兩者合併按日期降序 → `af`；扣除 `NEWS_REVIEW[url].nn` 者 → 有效新聞 `cnt`

## 五、例行更新三步驟

```bash
python tools/news-pipeline/update_fcu_news.py    # 1. 抓新文章，更新 index.html
node tools/extract-news.js                       # 2. 重算統計 → tools/news.json
python tools/sync-news-to-healthcheck.py         # 3. 同步進 health-check.html 新聞成效分頁
```

主更新器另有 `--force`（全量重爬）與 `--dept <id>`（單系更新）。原排程為每月 1 日 09:00。
第 3 步會自動備份 `health-check.html`，並以**網址主機名**對應兩邊的學系
（id 不完全一致：行銷系 `marketing`↔`mkt`、智慧城市學程 `msc`↔`imsc`）。
